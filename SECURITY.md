# Security Policy

## Reporting a vulnerability

Please avoid public issues for security vulnerabilities. Use GitHub's private security advisory flow when available, or contact the maintainer privately with the affected version, reproduction steps, and impact.

## Guidelines

- Never include secrets, tokens, or private credentials in bug reports.
- Prefer the smallest reproducible example.
- Keep dependencies and runtime versions current.
- Treat input files and network responses as untrusted data.
- Report security-sensitive behavior before publishing a proof of concept publicly.

## Response

Reports will be reviewed as soon as practical. Once a fix is available, the affected behavior and mitigation will be documented in the release notes or repository documentation.
